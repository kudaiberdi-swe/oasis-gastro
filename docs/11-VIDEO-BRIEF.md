# 11. Бриф для видео о Sandyq

> Всё, что нужно, чтобы снять ролик о проекте: суть, факты, сюжеты, структура, закадровый текст, шот-лист,
> бренд и что нельзя показывать. Цифры ниже проверены по коду на 2026-09-27 — не добавляйте к ним
> придуманные метрики (выручка, скорость, «на N % быстрее»): их у проекта нет.

## 1. Суть

**Одной фразой.** Sandyq — собственная касса и бэк-офис сети ресторанов казахской кухни: касса у стола,
экран кухни и офис с учётом, отчётами и персоналом — в фирменном стиле Sandyq и на двух языках.

**Абзацем.** Сеть Sandyq сегодня работает в iiko — сторонней платформе, общей для многих ресторанов. Sandyq
строит свою систему, чтобы со временем перейти на неё полностью. Сейчас это пилот на трёх филиалах (Алматы,
Шымкент, Түркістан): iiko остаётся источником реальных данных и только читается, а Sandyq уже умеет принимать
заказы у стола, отправлять их на кухню, проводить оплату, закрывать смены и вести учёт в офисе.

## 5. Сюжеты для показа

Каждый сюжет — 10–20 секунд экрана. В скобках — где снимать и под какой ролью (доступы — `10-TESTING-GUIDE.md` §0).

1. **Вход** (`/pos`, dev). Экран с логотипом и «Sandyq Алматы · Касса 1»; касание «Қазақша» — экран сразу на
   казахском. PIN набирать за кадром.
2. **Зал** (кассир). «Зал · N открыто» → сетка столов: занятые с суммой и временем, касание свободного — и
   чек открыт.
3. **Заказ** (кассир). Карточки блюд с фото и двумя названиями, модификаторы, «Гостей», «На кухню».
4. **Кухня** (`/kitchen`, во втором окне рядом). Тикет появляется сам, повар двигает его по колонкам.
5. **Оплата** (кассир). Выбор способа, наличные со сдачей → спокойный экран «Оплачено» → «Новый стол».
6. **Контроль денег** (кассир + менеджер). Скидка 15 % — касса просит PIN менеджера; закрытие смены: сначала
   пересчёт вслепую, потом «Сверить» — расхождение видно только после.
7. **Без связи** (DevTools → Offline). Полоса «Нет связи с сервером…», оплата заблокирована с причиной.
8. **Офис** (`/office`, администратор). Тёмный сайдбар из 12 групп, стартовая страница, «Все отчёты»,
   карточка блюда с ценами по филиалам.
9. **Данные iiko** (офис). «Корпорация → Обмен данными с iiko»: сопоставление филиалов и импорт — только чтение.
10. **Финал.** Знак Sandyq на тёмном фоне, орнамент, фраза из §1.

## 7. Шот-лист и подготовка

- **Где снимать — dev** (`http://localhost:5173`, запуск — `10-TESTING-GUIDE.md` §0.1). На prod реальные имена
  сотрудников и реальные продажи — его не снимайте.
- **Данные.** Перед съёмкой: `npm run seed`, `npm run test:credentials`; открыть смену, создать 3–4 заказа на
  разных столах, чтобы сетка зала была живой; один отправить на кухню.
- **Размер окна.** Касса — 1440×900 или 1280×800; кухня — 1920×1080; офис — 1440×900. Масштаб браузера 100 %.
- **Темы.** Каждый ключевой экран — в дневной и ночной (профиль сотрудника → «Тема»).
- **Чистота кадра.** Отдельный профиль Chrome без закладок и расширений, уведомления системы выключены.
- **Кадры кассы и кухни — одной командой:** `npm run video:capture`. Сценарий `e2e/video/capture.spec.ts` сам
  перевыпускает PIN тестового кассира на dev (как `scripts/e2e-pos.sh`), входит, проходит сюжеты 1–7 и кухню и
  кладёт в `reference/video-assets/day/` и `…/night/` скриншоты по сценам (`01-login` … `16-kitchen-cooking`)
  и запись экрана `pos-walkthrough.webm`, `kitchen-walkthrough.webm` (1440×900). Папка в `.gitignore`.
  Сцену, которая не удалась, сценарий пропускает и пишет об этом в лог — остальные кадры сохраняются.
- **Кадры офиса:** `SCREENS=1 npx playwright test e2e/screens --project=office-1440-day --project=office-1440-night`
  → `reference/app-screenshots/W0/office/` (оболочка и все 91 раздел на демо-данных, без входа).
- **Старые кадры** в `reference/app-screenshots/W0/pos` сняты до редизайна кассы — для ролика не берите.

## 8. Что нельзя показывать

- Коды, PIN и пароли — набирать за кадром; файл `test-credentials.local.md` в кадре не открывать.
- Адресную строку с `?terminal=` можно; с ключами, токенами или содержимым `.env` — нельзя.
- Реальные имена, телефоны, ИИН сотрудников и гостей (prod, разделы «Сотрудники», «Гости»).
- Ключи и секреты в Convex, GitHub, Azure; терминал с командами деплоя.
- Утверждения из §3 «Не говорите».
