> Для кого: владелец и любой, кто проверяет Sandyq руками перед запуском или после изменений.
> Логины, пароли и PIN в этом файле **не хранятся** (он в git). Они лежат в локальном файле
> `test-credentials.local.md` в корне репозитория — он в `.gitignore`, открывайте его в редакторе и
> никуда не пересылайте (ни в чат, ни в мессенджер, ни скриншотом).

Запуск dev: в одном терминале `npx convex dev`, во втором `npm run dev`.

### 0.2. Доступы

**Dev.** Сотрудники кассы создаются сидом: `npm run seed` (или `npm run seed:e2e`). Затем:

```
npm run test:credentials
```

Скрипт берёт самый свежий `.sandyq-seed/credentials-*.json` и пишет в `test-credentials.local.md` таблицу
«роль → код → PIN» (кассир, менеджер, администратор — во всех трёх филиалах) и список терминалов.
Значения в терминал не печатаются. Каждый новый сид выдаёт **новые** PIN — после него запустите скрипт ещё раз
(то, что вы вписали в файл руками, сохранится). Email и пароль офиса dev впишите в тот же файл сами.

**Prod.** Сид на prod PIN не создаёт. Для теста заведите отдельных тестовых сотрудников (§1.3) и впишите их
код и PIN в раздел «Prod» файла `test-credentials.local.md`. Вход в офис prod — ваш email
(`OFFICE_BOOTSTRAP_EMAIL`) и пароль, который вы задали при регистрации.

### 0.3. Правила для prod

- Касса — пилот **без фискальных чеков**, фискальные по-прежнему печатает iiko. Тестовые продажи не уходят в ОФД.
- Каждую тестовую продажу на prod помечайте комментарием «ТЕСТ» и сразу делайте по ней возврат (§2.5):
  выручка и остатки филиала не должны исказиться.
- Не проверяйте на prod то, что меняет реальные данные без нужды (цены, техкарты, остатки, зарплата) — это на dev.
- iiko только читается: в Sandyq нет кнопок, которые пишут в iiko, и так должно остаться.
- После проверки отключите тестовых сотрудников: «Сотрудники → Сотрудники» → карточка → «Отключить».

### 0.4. Как сообщать об ошибке

Окружение (dev/prod), адрес, терминал, роль, время, шаги, что ожидали и что увидели, скриншот.
**Без** кода и PIN — пишите «кассир из test-credentials».

## 1. Запуск prod — один раз (администратор офиса)

Сначала это, иначе на prod нельзя войти в кассу.

1. **Кассы.** «Администрирование → Терминалы» → касса филиала → переключатель «Активна». Выключенной кассы нет
   в выборе рабочего места.
2. **Блюда.** «Товары и склады → Номенклатура» → «Показать блюда iiko с ценой» → подтвердить. Блюда iiko
   приходят скрытыми; после этого в каждом филиале на кассе видны те, у которых есть цена этого филиала, а
   временное меню из PDF скрывается. На dev то же делает `npm run dev:iiko-menu`.
3. **Тестовые сотрудники.** «Сотрудники → Сотрудники» → «Новый сотрудник»: ФИО «ТЕСТ Кассир», роль
   «Кассир», филиал, код и PIN (форма предлагает свободные) → сохранить. Код и PIN показываются **один раз** —
   сразу впишите их в `test-credentials.local.md`. Так же «ТЕСТ Менеджер» (роль «Менеджер») и «ТЕСТ Кухня»
   (роль «Кухня»).
4. **Настоящие сотрудники** — тем же разделом, но из iiko: вкладка «Из iiko» → «Подключить» (или «Корпорация →
   Обмен данными с iiko → Доступ сотрудников к кассе OASIS Gastro»). PIN передавайте лично. Забытый PIN — карточка
   сотрудника → «Сбросить PIN».

Ожидаемо: на `/pos` prod в выборе рабочего места есть включённые кассы, тестовый кассир входит.

## 2. Кассир — `/pos`

Войдите как **Кассир**. Горячие клавиши: F2 — поиск, F4 — оплата, F8 — отложить, Esc — закрыть окно.

### 2.1. Вход и смена

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | Открыть `/pos` | Экран входа: логотип, «Sandyq <город> · Касса 1», «Код сотрудника» |
| 2 | Нажать «Қазақша», потом «Русский» | Экран сразу переводится и обратно |
| 3 | Ввести код → «Далее» → PIN | Вход; неверный PIN 5 раз подряд — блокировка на 10 минут |
| 4 | Первая продажа за день | Окно «Открытие смены»: наличность на начало → «Открыть смену» |
| 5 | Шапка | Пилюля «Смена №N · открыта ЧЧ:ММ», логотип Sandyq |
| 6 | Не трогать кассу 5 минут | Касса блокируется, нужен повторный PIN |

### 2.2. Зал и заказ

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | «Зал · N открыто» | Сетка столов по залам; на свободном — номер и места, на занятом — сумма, время, статус |
| 2 | Коснуться свободного стола | Сразу открывается чек этого стола, без клавиатуры |
| 3 | «Без стола» | Чек на вынос; строки «Обслуживание» нет |
| 4 | Добавить блюда касанием, F2 — поиск | Позиции в чеке; у блюда с казахским названием — вторая строка на казахском |
| 5 | Блюдо с модификаторами | Окно выбора; подпись модификаторов под позицией |
| 6 | «+» / «−»; «−» при количестве 1 | При 1 — вопрос «Убрать позицию?» с «Убрать» / «Отмена» |
| 7 | «Гостей: —» | Счётчик 1–30, сохраняется в чеке (только в зале) |
| 8 | «На кухню» | Позиции уходят на `/kitchen` (§4) |
| 9 | Строка «Обслуживание 15 %» | Есть в чеке стола, нет на вынос |
| 10 | Открыть второй стол, вернуться к первому через «Зал» | Оба чека живы, занятые столы видны в сетке |

### 2.3. Действия с заказом («Ещё»)

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | «Ещё» | 4 плитки: «Печать предчека», «Комментарий», «Перенести на стол», «Разделить чек»; ниже «Удалить позицию», «Перенести на кассу», «Отменить заказ» |
| 2 | Скидка до 10 % | Применяется без менеджера, видно «Итого после скидки» |
| 3 | Скидка больше 10 % | Нужен PIN менеджера |
| 4 | Снять обслуживание | Нужен PIN менеджера |
| 5 | «Перенести на стол» | Сетка зала, активны только свободные столы |
| 6 | «Разделить чек» | Часть позиций уходит в новый чек |
| 7 | «Удалить позицию», уже отправленную на кухню | С причиной и PIN менеджера; на кухне — отмена |
| 8 | «Отменить заказ» | PIN менеджера |
| 9 | F8 (отложить), потом вернуть из «Зала» | Статус «Отложен» (янтарный), чек возвращается |

### 2.4. Оплата

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | «Оплатить» или F4 | Окно «Оплата заказа»; способ **не выбран**, «Подтвердить» неактивна |
| 2 | Стрелки ← → по плиткам способов | Выбор переключается с клавиатуры |
| 3 | «Наличные» → сумма больше чека | Показана сдача |
| 4 | «Подтвердить · <сумма>» | Экран «Оплачено»: номер, способ, сдача; «Печать чека», «Новый стол» |
| 5 | Карта / QR / «Смешанная оплата» | Для смешанной сумма частей должна сойтись с заказом |
| 6 | «Новый стол» | Окно закрывается, чек снят с выбора |

### 2.5. История и возврат

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | Меню кассы → «История заказов» → найти заказ | Поиск по номеру, столу, позиции |
| 2 | Возврат | PIN менеджера; сумма не больше оплаченной, способ — как в оплате |
| 3 | После возврата | Статус «Возвращён» или «Частичный возврат» — цвет отличается от «Отложен» |

### 2.6. Деньги в кассе и закрытие смены

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | Меню → «Текущая смена» (кассиром) | Нет выручки и ожидаемой наличности — фраза, что их видит менеджер |
| 2 | «Внести / изъять» → «Внести наличные» | Сохраняется |
| 3 | «Изъять наличные» | Всегда PIN менеджера; больше, чем в кассе — «Сумма больше, чем учтено в кассе» |
| 4 | «X-отчёт» кассиром | PIN менеджера; смена не закрывается |
| 5 | «Закрыть смену» → ввести посчитанную сумму | До «Сверить» ожидаемая сумма **не видна** |
| 6 | «Сверить» | «Ожидается в кассе» и расхождение; при расхождении нужен комментарий, от 1000 ₸ — PIN менеджера; «Пересчитать» сбрасывает |
| 7 | Подтвердить закрытие | «Закрыть смену и напечатать Z-отчёт? Действие необратимо.» → Z-отчёт |
| 8 | Открытые чеки при закрытии | Закрыть смену нельзя, пока есть открытые чеки |

### 2.7. Устойчивость и настройки

| # | Действие | Ожидаемо |
|---|---|---|
| 1 | Выключить Wi-Fi (режим Offline в DevTools может не разорвать уже открытое соединение с сервером) | Полоса «Нет связи с сервером…», «Оплатить» и «На кухню» заблокированы с причиной рядом |
| 2 | Вернуть сеть | Полоса исчезает, кнопки активны |
| 3 | Профиль сотрудника (имя в шапке) | Тема, плотность, «Язык интерфейса» Русский / Қазақша, горячие клавиши |
| 4 | Переключить на «Қазақша» | Вся касса на казахском, у блюд первым — казахское название; остаётся после перезагрузки |
| 5 | Ночная тема | Текст читается, активная категория залита цветом |

## 7. Сквозной день (≈ 20 минут)

1. Кассир открывает смену (§2.1).
2. Два стола: по заказу с модификаторами, оба «На кухню» (§2.2).
3. Кухня проводит тикеты по статусам (§4).
4. Стол 1 — наличными со сдачей, стол 2 — смешанной оплатой (§2.4).
5. Возврат одной позиции со стола 1 с PIN менеджера (§2.5).
6. Изъятие наличных с PIN менеджера (§2.6).
7. Закрытие смены со слепым пересчётом → Z-отчёт (§2.6).
8. Офис: заказы, смена (принять), проводки, отчёт о продажах за день (§5).

На prod — тем же сценарием с тестовыми сотрудниками и комментарием «ТЕСТ»; после возвратов итог дня
филиала не должен измениться.
